- Keep logo edit instructions in the shared prompt builder, with reference roles matching upload order, so exact-text and correction fidelity rules can be regression-tested without live AI calls.
- Export saves distinguish mobile devices (including iPads with desktop user agents) from desktop computers: desktop downloads prepared Files via blob URLs, while mobile PNG saves synchronously invoke Web Share with explicit errors and no link fallback to avoid navigating away.
- Logo requests carry an explicit replacement or recreation mode through the shared prompt builder; both PNG backgrounds are rendered from the same traced vector before saving (renderPngPair), and other PNG sizes are prepared when picked, so a save tap never awaits work before native sharing.
- Shape-reshape mode first has a vision model write a text brief from both images, then sends only the original logo to the image editor, so it cannot copy the shape reference; uploads are flattened onto white first because transparency reads as solid black.
- Batch jobs snapshot their inputs and own their stream, abort controller, progress, and prepared exports; no shared busy flag or task count cap may serialize or overwrite independent results.
- Upload targets share useImageDrop for drag highlighting, image filtering, disabled-state handling, and file-drop navigation prevention; drops reuse the file-picker callbacks so task behavior stays identical.
- SVG export uses the in-house sub-pixel vectorizer in src/lib/vectorize.ts (auto ink/background detection incl. transparency, marching squares, corner sharpening, straight-line detection, cubic fitting at 0.35px, axis/edge alignment); keep it DOM-free so accuracy stays regression-tested against synthetic shapes and the real fixture in src/test/fixtures.
- "Exact trace" mode is client-only (TaskMode, not LogoMode): it vectorizes the untouched upload, keeps transparency, skips flattening and the AI, and renders PNGs from the vector when the source is under 1024px.
- AI redraw fidelity: clean uploads are sent as a 1024px black rendering of their exact trace (reference-prep.ts), with measured geometry passed as the "geometry"/"reference" form fields into the shared prompt builder (GEOMETRY LOCK for recreate only); recreate results show a shape-match score (hard IoU of normalized outlines, warn below 95%).

- Concepts: a round per press of Generate, one creative direction each. Grok is off by default (it failed constantly in live runs): a round is then 3 OpenAI concepts. The "Use Grok too" setting makes it 4 (CONCEPT_PROVIDERS: 2 OpenAI, 2 Grok) via conceptProviders(); UI counts follow the round size (roundSize(), round.concepts.length) — never hard-code 4. Prompts are built on the server from the brief by concept-prompt.ts (/api/concept never accepts a raw prompt): exact text with a character inventory, unique custom lettering (no stock fonts), flat logo on white with margin.
- Colour (src/lib/palette.ts, pure, tested): when a brief names no colours, the first round builds a palette from data — the reference search returns the visual query's thumbnails as `samples`, the browser measures each logo's chromatic hue families (logoSwatches; white, black and greys skipped), aggregateSwatches ranks hues by how many logos use them, and buildPalette applies colour theory: primary = the most used hue at its measured depth; accent = the colour real brands pair with it (≥ 2 logos) when it is a recognised harmony (analogous, triadic, split/complementary), else analogous for calm/refined and complementary for bold/playful personalities; neutral = primary-tinted near-black for lettering; primary ≥ 3:1 and neutral ≥ 7:1 contrast on white. No samples → colour-psychology hue by industry (INDUSTRY_HUES). The palette is written into brief.colors as "role name #HEX" and paletteLine locks it in the concept prompt (exact colours, no others, a job each). User-given colours always win.
- Quality hand-off (concept-pipeline.ts, dependency-injected and tested without live AI): draw → code checks (concept-checks.ts) + AI review (/api/review; spelling is failed when the reviewer's own reading doesn't contain the exact text) → fix only the failed blocking boxes as a local edit → recheck; BUDGET is 2 fixes per drawing, 1 fresh redraw, ~3 min, with backoff on 429. Each CheckDef is blocking or a note (checklist in concept-prompt.ts). Blocking: background, cut off, copying a reference, spelling, extra text, logo type, flat, broken shapes. Notes (shown amber on a passed concept, never hide it): clean vector, colour count, one colour, readable when small, matches the brief, reference roles — real AI output failed these constantly (live run: every concept hidden). Code checks run on a despeckled image (despeckle: isolated blobs under speckSize ≈ 30 px at 1024² — JPEG noise from Grok — painted with the background; sparkles/dots are bigger and stay), and measureConcept also ignores noise-sized blobs so they can't move edges or sizes. "Cut off" means artwork reaches the outermost pixels (close is fine: exports are re-centred). Small-size legibility is judged on the solid ink shape at a 48 px short side (threshold 0.6). The chosen concept is despeckled before tracing (cleanConcept). A failed concept stays hidden but offers "Show anyway" (badge + failed boxes listed, usable).

- Exact traces go through vectorizeDetailed, whose settings come from traceSettings(edgeSoftness) as a continuous ramp in source pixels (never a hard crisp/soft switch, which made borderline uploads flip to traced pixel steps): every trace gets arc-length Gaussian outline smoothing (radius shrinks near corners and tight bends) and curve fairing, scaled up with softness along with tolerance but capped (very blurry uploads already have smooth 50% edges; uncapped growth melted letters); opaque-background coverage cuts the bottom/top 10% symmetrically so compression speckle doesn't read as softness; the exact-trace accuracy score is hard IoU at the 50% edge so blur isn't scored as trace error; non-soft small crops are bicubic-upsampled (≈3000px long side) with all distances scaled by the factor (corner distances only as softness rises, so tiny lettering keeps fine corners), while clearly soft uploads trace at source resolution because upsampling turns their pixel steps into outline detail.
- Colour: exact traces default to black & white; src/lib/color-trace.ts (pure, DOM-free) first floods the background from the border (opaque images; it must never merge with ink through soft edges), then grows regions across small colour steps with a lagging "trail" colour (gradients stay one region, soft edges and halos stop growth), drops tiny/sliver regions into fractional edge shares, fits flat or multi-stop linear gradients, traces each region with vectorizeScaled at one shared scale/softness and overlaps later layers by 2px to hide seams. adviseColor scores 0–100 how much black & white loses; the workspace shows it with a Black & white | Colour switch (colour traced on first request, then cached). Images carry colour profiles (e.g. Display P3): always read pixels through the browser canvas, which converts to sRGB.
- Export canvas: every export (single and batch) defaults to the 1300 × 1200 design board (src/lib/board.ts): logo centred on its true outline (curves sampled) and scaled into a safe box of 56% width × 42% height (matches the reference board); "Logo only" keeps the tight crop. Colour results from a coloured upload offer and default to the upload's own background ("Brand") for PNGs; colour accuracy is compared on that background. Colour halo filtering only drops small/thin regions that have no interior pixels or whose colour is a blend of (or near) a neighbour, so fine lettering survives.
- Soft shading (src/lib/shading.ts, pure): each colour region's fill is fitted from pixels ≥3px inside its outline as flat, linear or elliptical radial (grid search over centre/aspect, chosen when it beats linear by 25%), then large regions get up to 5 radial highlight/shadow overlays fading to transparent (stop-opacity), found as peaks in a smoothed residual map; overlays reuse the region's outline (isOverlay) and are excluded from outline stats, board bounds and black & white drawing. Thin appendages of a big region (stems) whose colour differs from the body are split off by a morphological opening. On opaque images every pixel within 2px of a boundary is shared between neighbours using each side's local colour (not the fitted gradient), so soft edges trace smoothly. Gradient ids are prefixed with a content hash so pasted SVGs don't clash; parseSvg reads radial gradients back (only the vertical-scale transform this app writes).
- OpenAI errors (openai-text.server.ts): classifyOpenAIError reads the error body, because OpenAI answers 429 both for rate limits and for an account with no credit ("insufficient_quota"). Out of credit → 402 with a plain "add credit in Billing" message; bad key → 401 naming OPENAI_API_KEY; neither is ever retried. Real rate limits are retried server-side (RATE_RETRIES, honouring retry-after) and then reported honestly — never claim "retrying" where nothing retries. /api/concept maps image errors the same way, so the concept loop (isRetryable) retries only 429/5xx.
- Link references (link-reference.ts pure + tested, link-reference.server.ts, /api/link-reference): URLs in brief notes (at most MAX_LINKS) are opened before the brief model runs, in useBriefJob.makeBrief, so Create and Batch both get them. The role comes from the closest role word on the link's line (roleNear; generic words like "reference" or "inspiration" mean style). The page's images (share image, preloaded images, page images, icons; up to 4) become one 2 × 2 white contact-sheet PreparedRef, read for that role only and fingerprinted like uploads. Its title and description go to the brief model as a labelled context line. The review panel also has "Add a link". The server fetches only public http(s) URLs (isPublicUrl: no localhost, private/link-local IPs, internal names, credentials or odd ports), follows redirects by hand and re-checks every hop, and caps time and size. Nothing is stored. A link that fails never blocks: job.notice explains it.

- Concept planning (concept-plan.ts pure + tested, /api/concept-plan): before each round is drawn, gpt-5-nano (structured output, effort low) art-directs it — one genuinely different idea per concept (name, idea grounded in brief.story, symbol, lettering, colour use, layout), spreading strategies (story symbol, monogram, wordmark-led, emblem, abstract) and avoiding ideas earlier rounds tried. The brief keeps a client's existing idea in brief.direction ("existing direction, open to refinement"), never in mustHave/summary: exactly one concept refines it, the rest explore (live run: all three concepts were the client's thin ring + T). Plans travel to /api/concept as bounded structured fields (normalizePlan; never a raw prompt), are stored on the round (Round.plans) and name the concept cards; planning failure falls back to fallbackPlans and never blocks. Craft rules in DESIGN_RULES/paletteLine: no hairlines (thinnest stroke ≈ 4% of logo height, lettering regular-to-bold), type hierarchy for multi-word names (descriptor words smaller, spaced), all lettering one colour (never a colour per word), 1–3 colours. The blocking code check "weight" fails artwork whose average stroke width (2 × ink area ÷ ink outline) is under LIMITS.stroke = 1.8% of the artwork's short side (real hairline concepts measured 0.5–1%, real logos 10–40%); its fix asks for strokes about twice as heavy.
- One concept at a time (useBriefJob redraw / recreate / addConcept, each with its own abort controller in `extras`, all aborted by cancel or a new round): Redraw restarts one concept from its planned idea in place; New version (ConceptDetail, optional "Change something…" text) appends a new concept seeded from that concept's image — runConcept({seed}) draws it through /api/concept with `image` + `recreate` (buildRecreatePrompt: apply the change, or a fresh better-crafted take on the same idea; exact text and craft rules still hold) and fresh redraws keep the seed; Add concept (header, key A) plans one new idea (planConcepts count 1, avoiding tried ideas) and appends it to the newest round. Rounds hold up to MAX_CONCEPTS = 12 (the server accepts concept indexes 0–11).
- Style follows the brand, not a house style (user: LOGOO must be able to make a ChatGPT-style bold restaurant badge — illustrated chicken and flames, hand-lettered name, slogan, ~5 colours). DESIGN_RULES and the planner keep the craft rules (no hairlines, type hierarchy, one colour for all lettering) but match style and detail to the category and references: minimal for corporate/medical/tech, bold and illustrative allowed for food, hospitality, street, sports and craft (up to 5 flat colours; the literal product drawn with character is fine, generic stock clichés are not). The planner follows the client's references first ("REFERENCES FIRST") and only uses strategies that suit the category (badges/mascots/hand-lettering for takeaways, not abstract marks). BRIEF_INSTRUCTIONS map restaurants/takeaways/grills/food trucks/bakeries to emblem or combination with emblem + mascot as alternatives, and the AI review's "type" check accepts the brief's alternative types so a badge isn't failed as the wrong type.
