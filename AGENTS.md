- Keep logo edit instructions in the shared prompt builder, with reference roles matching upload order, so exact-text and correction fidelity rules can be regression-tested without live AI calls.
- Export saves distinguish mobile devices (including iPads with desktop user agents) from desktop computers: desktop downloads prepared Files via blob URLs, while mobile PNG saves synchronously invoke Web Share with explicit errors and no link fallback to avoid navigating away.
- Logo requests carry an explicit replacement or recreation mode through the shared prompt builder; both PNG backgrounds are rendered from the same traced vector before saving (renderPngPair), and other PNG sizes are prepared when picked, so a save tap never awaits work before native sharing.
- Shape-reshape mode first has a vision model write a text brief from both images, then sends only the original logo to the image editor, so it cannot copy the shape reference; uploads are flattened onto white first because transparency reads as solid black.
- Batch jobs snapshot their inputs and own their stream, abort controller, progress, and prepared exports; no shared busy flag or task count cap may serialize or overwrite independent results.
- Upload targets share useImageDrop for drag highlighting, image filtering, disabled-state handling, and file-drop navigation prevention; drops reuse the file-picker callbacks so task behavior stays identical.
- SVG export uses the in-house sub-pixel vectorizer in src/lib/vectorize.ts (auto ink/background detection incl. transparency, marching squares, corner sharpening, straight-line detection, cubic fitting at 0.35px, axis/edge alignment); keep it DOM-free so accuracy stays regression-tested against synthetic shapes and the real fixture in src/test/fixtures.
- "Exact trace" mode is client-only (TaskMode, not LogoMode): it vectorizes the untouched upload, keeps transparency, skips flattening and the AI, and renders PNGs from the vector when the source is under 1024px.
- AI redraw fidelity: clean uploads are sent as a 1024px black rendering of their exact trace (reference-prep.ts), with measured geometry passed as the "geometry"/"reference" form fields into the shared prompt builder (GEOMETRY LOCK for recreate only); recreate results show a shape-match score (hard IoU of normalized outlines, warn below 95%).
- UI: LOGOO, an all-black studio (theme tokens in styles.css :root, color-scheme dark; no hard-coded light colours in app chrome — use field/line/success/pending tokens). Logo artwork always sits on its own soft grey artboard (--artboard / --artboard-alt; never pure white unless white is the real export background) so black logos stay visible; generated concept images are multiplied onto the grey tile so their baked-in white reads as grey: white concept tiles, and in the workspace a black canvas whose only light surface is the export artboard itself (the 1300 × 1200 board, or the tight "Logo only" crop) showing the real export background (grey checkerboard for transparent, white or brand); Outlines sit on a grey paper card. There are no canvas background swatches. The header logo is the LOGOO wordmark only (brand.tsx, traced with the in-house vectorizer, currentColor, small). Three sections (src/routes/index.tsx, app-header.tsx): Create (default, concepts first: "Generate concepts" goes straight from notes to a round of 4; "Review brief first" opens the editable brief card; each "4 more concepts" stacks a new round on top and earlier rounds stay, see useBriefJob rounds), Batch (many briefs) and Import (the original upload flow, src/components/import-logo.tsx, still starting on Exact trace via DEFAULT_TASK_MODE; DEFAULT_LOGO_MODE stays its default AI mode). Create and Batch stay mounted (hidden) while the workspace or Import is shown, so running jobs never stop. The workspace draws the logo from parsed outlines (outline.ts), never injected SVG markup. Recent results and settings live only in localStorage, every access guarded. Settings (identity package, mockups) are opt-in and marked coming soon.
- Outlines view legibility (user reference: an O with dashed outline over a pale fill, dashed guides at top and bottom): contours are grouped by on-screen size (outlineTiers in outline.ts, pure, tested) — large ones get 2px dashes "8 5" over a 5px paper-coloured halo so close contours stay apart, medium ones shorter dashes and a 3px halo, small ones (fine lettering, counters) a thin solid line so dashes never chop them apart. Strokes are in screen pixels (non-scaling); the Outlines canvas stays light paper on the black UI.
- Pasted briefs: /api/brief runs cleanPastedBrief (src/lib/clean-paste.ts, pure, tested) before the model, removing menus (runs of short lines), headers/footers, cookie/legal/social/newsletter lines, breadcrumbs, bare URLs and repeats while keeping link text; BRIEF_INSTRUCTIONS also tell the model to ignore any page chrome that survives. The composer shows how many clutter lines will be left out.
- Providers: OpenAI (direct, OPENAI_API_KEY) and Grok (xAI, XAI_API_KEY) only. Gemini and the Lovable AI gateway are removed and must not come back. Text work (brief cleanup, reference reading, concept review) uses the cheapest OpenAI model (TEXT_MODEL = gpt-5-nano in openai-text.server.ts) with structured outputs; images use gpt-image-2 and grok-imagine-image.
- Brief (src/lib/brief.ts, pure): messy notes → /api/brief → structured LogoBrief. Brand name and tagline are copied exactly, never corrected. Nine static logo types (Figma's list minus animated/3D/dynamic, which belong to identity/mockups); Combination mark is DEFAULT_LOGO_TYPE and the model's prior. References carry one role (typography, style, colour, layout, concept, mood); the vision model describes only that quality as text, colour palettes are measured on the device, and the image models never see reference pictures, so they can't copy them.
- Concepts: 4 per brief (CONCEPT_PROVIDERS: 2 OpenAI, 2 Grok, one creative direction each). Prompts are built on the server from the brief by concept-prompt.ts (/api/concept never accepts a raw prompt): exact text with a character inventory, unique custom lettering (no stock fonts), flat logo on white with margin.
- Quality hand-off (concept-pipeline.ts, dependency-injected and tested without live AI): draw → code checks (concept-checks.ts: background, margin, specks, colour count, colour reliance, small-size legibility, copying a reference; thresholds tuned on the fixtures) + AI review (/api/review; spelling is failed when the reviewer's own reading doesn't contain the exact text) → fix only the failed boxes as a local edit → recheck; BUDGET is 2 fixes per drawing, 1 fresh redraw, ~3 min, with backoff on 429. A concept is never shown (its image stays blurred) unless every box passes.
- Chosen concepts go through Exact trace (concept-result.ts) so they export like uploads; colour is shown first when the trace advises it. Every export also offers Adobe Illustrator: ai-export.ts (pure) writes a PDF-compatible .ai from the exported SVG (solid fills, linear/radial gradients, fading overlays as luminosity soft masks), prepared with the result so mobile saves stay synchronous.
- Batch briefs (brief-batch.tsx): each card owns a useBriefJob (its own brief, concepts, abort controller and prepared files), starts on mount and cancels on unmount; no shared busy flag or cap.
- Exact traces go through vectorizeDetailed, whose settings come from traceSettings(edgeSoftness) as a continuous ramp in source pixels (never a hard crisp/soft switch, which made borderline uploads flip to traced pixel steps): every trace gets arc-length Gaussian outline smoothing (radius shrinks near corners and tight bends) and curve fairing, scaled up with softness along with tolerance but capped (very blurry uploads already have smooth 50% edges; uncapped growth melted letters); opaque-background coverage cuts the bottom/top 10% symmetrically so compression speckle doesn't read as softness; the exact-trace accuracy score is hard IoU at the 50% edge so blur isn't scored as trace error; non-soft small crops are bicubic-upsampled (≈3000px long side) with all distances scaled by the factor (corner distances only as softness rises, so tiny lettering keeps fine corners), while clearly soft uploads trace at source resolution because upsampling turns their pixel steps into outline detail.
- Colour: exact traces default to black & white; src/lib/color-trace.ts (pure, DOM-free) first floods the background from the border (opaque images; it must never merge with ink through soft edges), then grows regions across small colour steps with a lagging "trail" colour (gradients stay one region, soft edges and halos stop growth), drops tiny/sliver regions into fractional edge shares, fits flat or multi-stop linear gradients, traces each region with vectorizeScaled at one shared scale/softness and overlaps later layers by 2px to hide seams. adviseColor scores 0–100 how much black & white loses; the workspace shows it with a Black & white | Colour switch (colour traced on first request, then cached). Images carry colour profiles (e.g. Display P3): always read pixels through the browser canvas, which converts to sRGB.
- Export canvas: every export (single and batch) defaults to the 1300 × 1200 design board (src/lib/board.ts): logo centred on its true outline (curves sampled) and scaled into a safe box of 56% width × 42% height (matches the reference board); "Logo only" keeps the tight crop. Colour results from a coloured upload offer and default to the upload's own background ("Brand") for PNGs; colour accuracy is compared on that background. Colour halo filtering only drops small/thin regions that have no interior pixels or whose colour is a blend of (or near) a neighbour, so fine lettering survives.
- Soft shading (src/lib/shading.ts, pure): each colour region's fill is fitted from pixels ≥3px inside its outline as flat, linear or elliptical radial (grid search over centre/aspect, chosen when it beats linear by 25%), then large regions get up to 5 radial highlight/shadow overlays fading to transparent (stop-opacity), found as peaks in a smoothed residual map; overlays reuse the region's outline (isOverlay) and are excluded from outline stats, board bounds and black & white drawing. Thin appendages of a big region (stems) whose colour differs from the body are split off by a morphological opening. On opaque images every pixel within 2px of a boundary is shared between neighbours using each side's local colour (not the fitted gradient), so soft edges trace smoothly. Gradient ids are prefixed with a content hash so pasted SVGs don't clash; parseSvg reads radial gradients back (only the vertical-scale transform this app writes).
